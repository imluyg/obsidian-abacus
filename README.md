# Abacus

Obsidian 字数统计插件。核心原则：**只存事实，不存结论**。

## 为什么不用现成的

`better-word-count` 的口径是「总量重算取差」。你库里 828 天的历史数据可以验证它有多不可靠：

- 自称总共 278 万字，实际约 63.6 万汉字 + 5.7 万英文词
- 单日最高记录 1,413,934 字（那是批量导入）
- 出现过 −119 万、−192 万两次断崖

原因很简单：把「库的总字数」当成状态，任何导入、删除、移动都会污染当天的写作量。

## 模型

两个东西分开存：

```
stats/snapshot.json        存量：每个文件现在多少字（可全量重建）
stats/ledger/YYYY-MM.jsonl 流量：逐次追加的事件（永不改写）
```

事件长这样：

```json
{"t":1763200000000,"p":"创作/小说/1/第一章.md","add":[820,12],"del":[35,0],"src":"edit"}
```

`add` / `del` 都是**向量** `[汉字, 英文词]`，从不合并成一个「总字数」。
周、月、年、项目、连续天数全部是这份账本的视图，加新图表不用改数据结构。

### src 的含义

| src | 含义 | 算不算写作 |
|---|---|---|
| `baseline` | 首次建库 | ❌ 不写账本 |
| `edit` | 本机正常编辑 | ✅ |
| `scan` | 启动时发现的差异（离线 / 同步） | ✅ |
| `delete` | 删文件 | ❌ 只记删减 |

首次建库**不写账本**，否则 63 万字会全部砸在当天。

## 面板

- **今日**：汉字大字 + 英文词 + 删改（单列，不混进主数字）
- **连续 N 天**：今天还没写不算断，昨天没写才算断
- **7 天 / 30 天**：切换趋势柱状图
- **本周 / 本月 / 全库**：三个存量与流量指标
- **项目**：本月新增 + 累计；默认按路径前两段分（`创作/小说`、`归档/日记`），可在设置里用 `名称 = 路径前缀` 细分到单本书
- **当前文件**：正在编辑的这篇多少字

## 周报

命令面板 → `生成本周周报`，写入 `归档/统计归档/周报 YYYY-Www.md`（同名覆盖）。

周报目录**自动排除在统计之外**，否则生成的周报会在下一次统计里被当成「今天写的字」，形成自反馈。

## 计数口径

- 汉字按字计，英文/数字按词计，两者分开
- 默认不计 YAML frontmatter、代码块、行内代码
- 去掉 Markdown 符号、URL、图片；双链取显示名
- 编辑时用「公共前后缀裁剪」只数改动段，所以「删一段再写一段」能拿到真实的增删

注意：靠 dataviewjs 渲染、数据全在 YAML 属性里的笔记（比如 `财务记录2024.md`），
按这套口径只有标题文字被计入——这是设计选择，不是 bug。

## 开发

```bash
npm install          # 只需要 typescript + obsidian 类型
node build.mjs       # 类型检查 + 打包 main.js
node build.mjs --test --vault="E:/path/to/vault"   # 跑测试（含真实库全量扫描）
node deploy.mjs      # 安装到 .obsidian/plugins/abacus
```

项目放在 `<库根>/.abacus/`，Obsidian 不索引点开头的目录，
所以 `node_modules` 不会污染关系图和搜索。

打包没用 esbuild：它要 spawn 子进程走管道，在受限环境里会 EPERM。
`build.mjs` 用 TypeScript 自己的 `transpileModule` 逐文件编译，
再用四十行模块表拼成单文件，全程在当前进程内完成。

## 数据丢失风险

`stats/ledger/*.jsonl` 删掉就没了 —— 它是唯一无法重建的东西。
`snapshot.json` 随时可以删，下次启动会重扫。

## 自动周报与备份

- **自动补上周周报**：启动时检查一次，上周有写作但没有周报文件才生成，已有文件不动。可在设置里关闭。
- **补生成上周周报** / **生成本周周报**：命令面板，后者用于周中随时查看。
- **导出账本备份**：把 `ledger/*.jsonl` 合并成一个 JSON 写到 `归档/统计归档/账本备份/账本备份 YYYY-MM-DD.json`。

最后一条是针对真实风险的：账本住在 `.obsidian` 下，`remotely-save` 默认不一定同步它。
导出到普通笔记目录后，那份 JSON 才会跟着同步走——这才是异地备份。

空周不会生成周报文件，避免给没写过字的周留下占位垃圾。

## 账本完整性

账本是唯一无法重建的东西，所以有三道保险：

1. **追加前修尾**：如果文件末尾是被截断的半行（同步冲突、断电），先截掉再追加。
   否则新行会粘在坏行后面，那一行就永久损坏了——而且你看不出来。
2. **启动体检**：只查最近两个月，发现坏行、截断或重复才弹提示，正常时完全静默。
3. **手动体检**：命令面板 →「检查账本完整性」，有问题时写成 `账本体检 YYYY-MM-DD.md`
   放进周报目录（该目录不计入统计）。

体检四项：无法解析的行、末尾缺换行的文件、重复事件（同一事件被写了两次）、
时间戳在未来的事件（时钟或时区错乱）。

发现异常时不要手工改账本，先「导出账本备份」留底再排查。

## 性能与写放大

实测（本机，1181 篇 / 63.5 万汉字）：

| 场景 | 数据量 | 耗时 |
| --- | --- | --- |
| 账本追加（快路径） | 1,500 行 / 115 KB | 0.45 ms |
| 账本追加（快路径） | 20,000 行 / 1.5 MB | 0.45 ms |
| 账本追加（旧：整文件重写） | 1,500 行 / 115 KB | 1.36 ms |
| 账本追加（旧） | 20,000 行 / 1.5 MB | 8.80 ms |
| 账本读取解析 | 1,500 行 | 1.66 ms |
| 快照写盘 | 1,181 条 / 52 KB | 1.48 ms |

所以瓶颈从来不是 CPU——真正的问题是每次编辑都整写 115 KB 账本 + 52 KB 快照。
现在两处都改了：

1. **账本走追加**：文件大小与上次写完后一致，就直接 `adapter.append`，
   写放大从 115 KB 降到约 120 字节，且耗时与文件大小无关。
   大小对不上（同步、手改、截断）立刻退回「读全文 → 修尾 → 整写」。
   这个判断只在"我们上次写完到现在没人动过"时成立，所以是安全的。
2. **快照降频**：快照随时可由全量扫描重建，没必要追着每次编辑写。
   去抖从 4 秒改成 30 秒，退出时再补一次。

`npm test` 的 `[6] 性能实测` 会打印这两项数字，改坏了能立刻看出来。

### 健康角标

体检结果不弹窗，改成**常驻显示**：

- 面板底部：`账本正常 · N 个月 · M 条`，异常时变成 `⚠ 账本异常 K 项 · 点击排查`
- 状态栏：异常时数字后面跟一个 `⚠`，悬停能看到第一条问题

启动时弹一次 Notice 的做法已经去掉——你要是那一刻没看屏幕就永远错过了。
异常现在不会自己消失，只有修好才会。

## 目标

设置里可以填每日 / 每周目标（按汉字计，填 0 表示不设）。设了之后：

- 面板顶部出现进度条，达标后变绿
- 周报里多一行「达标天数」

## 项目下钻

点面板里的项目名，展开该项目本月改动最多的几个文件；再点一次收起。
本月没有改动的项目，会退而显示该项目里最重的几篇。

数据全部来自账本，不需要额外扫描。

## 笔记属性（可选，默认关闭）

打开「保存时把字数写进属性」后，内容变化时会把汉字数写进 frontmatter：

```yaml
words: 3210
```

用途是让 Bases / Dataview 能按字数排序、筛选、做公式，不是替代账本——
分量在账本里，属性里只有一个汉字数（英文词去账本看）。

两个安全设计：

- **只在内容真的变化时写**，值没变就不动文件。否则会「写属性 → 触发 modify → 再写」死循环。
- **默认关闭**，因为它会修改你的笔记；属性名可改，默认 `words`。

也可以用命令面板的「把字数写入当前笔记属性」手动写一次。

## 年度报告与 CSV

命令面板 →「生成年度报告」，写入 `归档/统计归档/年度报告 YYYY.md`：

- **总览**：全年新增 / 删改 / 净增长、活跃天数、写作日均、最长连续、最高产一天
- **热力图**：HTML 表格，颜色越深写得越多，悬停看当天数字；用主题变量 + opacity，
  深浅色主题都不用单独适配
- **逐月 / 项目 / 改动最多的文件**：三张表

「导出账本 CSV」按天汇总成 `账本导出 YYYY-MM-DD.csv`：
日期、汉字新增、英文词新增、汉字删改、英文词删改、事件数。

两者都只读账本，随时可以重新生成，不会反过来影响统计。
